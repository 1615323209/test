## 重要指导原则

### 实体分类（极其重要！）
- **角色**: 有意识、能行动、有对话的个体（人、妖、神、魔等）
- **势力**: 有组织的群体 — 宗门、家族、帮派、王朝、军队、杀手组织、商盟等。必须有名称和成员（≥2人）。**街道、城市、建筑是地点，不是势力！**
- **势力层级**: 同一组织的不同分支/分部应归为同一个势力。例如"三区执法者"、"二区执法者"、"一区执法者"都应注册为**一个势力**（如"极光城执法者"），各区只是其管辖范围，不要拆成多个。后续发现新分支时用 `是否更新: true` 补充成员和势力范围
- **地点**: 地理/物理场所 — 城市、街道、建筑、山脉、秘境、洞府等
- **地点层级（极其重要！）**: 必须填写 `所属区域` 字段来建立层级关系。例如：
  - 极光界域 > 一区 > 寒霜街 > 寒霜街128号
  - 每个地点都要指明它属于哪个更大的区域。最外层（无上级）的填所属区域为空
  - **关键**: 如果你在 `所属区域` 中引用了某个地点（如"冰泉街"），该地点本身也必须在本批次或之前批次中注册为实体。不要只注册子节点不注册父节点！如果父节点首次出现，同时注册它（设置 `是否新实体: true`）
  - 这样最终报告才能展示完整的世界树状结构
- **能力**: 功法、武技、法术、血脉能力、神器功能等。如果能力属于某条道途，必须填`所属体系`指向该道途
- **道途与修炼体系（极其重要！请严格遵循！）**:

  修炼体系的层级结构（从上到下）：
  ```
  十四神道（顶层框架，类别=体系）
    ├── 兵神道（类别=体系，所属体系=十四神道）
    │     ├── 天狼路径（类别=道途，所属体系=兵神道）
    │     │     ├── 【铁衣】（类别=能力，所属体系=天狼路径）  ← 该路径的具体阶名/能力
    │     │     └── 【青甲】（类别=能力，所属体系=天狼路径）
    │     ├── 审判路径（类别=道途，所属体系=兵神道）
    │     └── 修罗路径（类别=道途，所属体系=兵神道）
    ├── 医神道（类别=体系，所属体系=十四神道）
    │     └── 血屠路径（类别=道途，所属体系=医神道）
    └── ...（共14条神道，每条下有若干路径）
  ```

  核心规则：
  1. **先注册框架再注册子项**：首次遇到修炼体系时，先注册"十四神道"（体系），再注册具体的神道和路径
  2. **道途只注册一次**：道途（如"天狼路径"）注册后，后续批次用 `是否更新: true` 补充信息，不要重复创建
  3. **能力的所属体系必须指向其直接父级**：如"铁衣"→"天狼路径"，"杀戮舞曲"→"审判路径"，不要跨级指向兵神道
  4. **阶名只填文中实际出现的**：文中的阶名可能是"铁衣""青甲""银胄"等具体名称，不要用"一阶/二阶/三阶"代替。文中未揭示的阶名不要编造，留空。每发现一个新阶名就通过更新补充
  5. **道途本身有等级体系**：每个道途应填`等级体系`字段，记录总阶数和已知的阶详情（阶名、进阶方式、获得能力、代表人物）
  6. **不要重复注册**：已在道途的"等级体系.阶详情"中描述的阶名/阶能力，不要再单独创建能力实体！能力实体用于记录不属于任何道途的独立功法、法宝、系统能力等。道途的每一阶本身已经通过等级体系完整描述了
  6. **独立法宝/能力**：不属于任何道途的法宝（如祭器、U盘）、系统能力（如观众期待值系统）、通用能力等，`类别`填对应的（法宝/系统能力/天赋等），`所属体系`留空
  7. **禁止重复**：不要把同一个东西既注册为"道途"又注册为"能力"。道途是框架，能力是框架下的具体技能/阶名
- 每个新实体分配唯一稳定ID: `char_拼音名` / `fact_拼音名` / `loc_拼音名` / `pow_拼音名`
- 如有别名/称号/昵称，务必列在aliases中
- 网文中同一角色可能有多个称呼: 本名、称号、外号、尊称等，请统一识别
- 仅为**新出现或状态有重大变化**的实体生成完整记录

### ID与名称使用规范（极其重要！违反将导致数据损坏！）
- **id字段**: 唯一允许放ID的地方。格式: `char_拼音名` / `fact_拼音名` / `loc_拼音名` / `pow_拼音名`
- **所有文本字段**: 必须使用**中文名称**，绝对不要填ID！这包括但不限于：
  - 角色名（如"陈伶"而不是 char_chenling）
  - 地点名（如"寒霜街"而不是 loc_hanshuangjie）
  - 势力名（如"黄昏社"而不是 fact_huanghunshe）
  - 能力名（如"焚天诀"而不是 pow_fentianjue）
- **所属势力字段**: 势力中文全称（如"兵部"），不要填 `fact_xxx`！
- **关系网中的"对象"字段**: 角色中文名（如"陈伶"），不要填 `char_xxx`！
- **涉及角色、出场角色、涉及地点等列表字段**: 全部用中文名，不要用ID！
- **成员列表、使用者列表**: 用角色中文名，不要用ID！
- **先注册后引用**: 如果你在关系网或势力中引用了一个角色，该角色必须已在"实体更新"中注册（设置is_new=true）

### 状态追踪（重要）
- 每个实体的"状态"字段必须准确: 活跃/已死亡/失踪/未知
- 如果本批次内某个角色死亡，必须将其状态设为"已死亡"

- 实体更新时，即使角色在其他方面没有变化，只要状态变了就要记录（设置"是否更新": true）

### 矛盾检测
- 如果角色在之前显示死亡但在此再次出现，标注矛盾
- 如果设定与之前描述不一致，标注矛盾
- 如果时间线出现明显混乱，标注矛盾
- **特别注意**：对比下方"关键事件日志"中的历史事件，如果当前批次的内容与之矛盾（如之前记录某角色心脏被泯灭并确认死亡，当前批次该角色却存活），必须在"与前文矛盾"中标注
- 只在确实发现矛盾时才输出，不要编造

### 关键事件记录（重要）
在本批次的"叙事摘要.关键事件"字段中，记录本批次发生的**不可逆的、对故事状态有根本性改变**的事件。
仅记录以下类型：
- **死亡**: 重要角色（主角、重要配角、反派）的死亡，简述死亡方式和确认程度
- **复活**: 已确认死亡的角色重新出现
- **毁灭**: 世界/大陆/势力/重要地点的毁灭性破坏
- **身份揭露**: 角色重大身份曝光（如隐藏多年的卧底身份被揭穿）
- **不可逆伤害**: 丹田破碎、心脏粉碎、修为尽废等不可修复的损伤
- **封印解封**: 重要封印的施加或解除
- **重大转折**: 足以改变整个故事走向的关键事件

不要记录：
- 普通战斗胜负（除非导致死亡或不可逆伤害）
- 日常对话或普通信息揭示
- 可逆的暂时状态变化（如受伤但后续治愈）
