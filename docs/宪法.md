## 第二章 四层 loop 架构

```
┌─ L4 实盘验证 ← L3 回测评估 ← L2 批次筛选 ← L1 单因子精炼 ─┐
│  (实盘偏差检测)  (双集回测)     (去重/正交)   (LLM生成)     │
└──────────────────────┬───────────────────────────────────┘
                       │ 事件总线（回滚→补位 / 批完成→回测 /
                       │ regime变化→复核 / 数据就绪→例行）
                       ▼
             检查点 / dashboard / 各层日志（全程留痕）
```

- **L1 管"这个因子行不行"**（生成 + 多周期 IC 体检）
- **L2 管"哪些值得留"**（去重 + 正交化 + regime/半衰期/反因子验证）
- **L3 管"池子对策略有没有用"**（训练/验证双集回测 + 多重检验校正）
- **L4 管"实盘到底灵不灵"**（模拟盘跟踪 + 序贯检验 + regime 感知）

因子状态机：`候选 → 启用 → 实盘确认 / 回滚`。上层只对下层交付的成果做决策，下层不感知上层。

**样本切分原则**：全历史 2021-2026 一分为二——**训练集 2021-2024**（L1/L2 筛选、L3 初步判定唯一可用区间）与**验证集 2025-2026**（仅 L3 复核用）。L1/L2 阶段 LLM 与筛选流程**不可见**验证集数据（防信息泄漏）；验证集指标达标才"确认启用"。

## 第三章 决策与回滚规则

1. **启用**：L3 判定"确认启用"→ 因子进入 v7 打分，状态=启用。**权重按 四层loop架构细则/L3 的动态规则计算（信号强度归一化 + 总权重约束），不使用固定值**。
2. **观察**：指标临界 → 下轮回测重点复核，连续 2 次观察无改进 → 回滚。
3. **回滚**：状态=回滚，因子从打分中移除，但**保留全部记录与数据**（仅标记废弃）。
4. **批量回滚**：若启用新因子后整体回测比"启用前"差 → 回滚该批次全部因子（先回滚，再告警）。
5. **实盘回滚（L4）**：实盘偏差超阈值 → 因子从模拟盘打分移除，状态=回滚，写 reason。
6. 任何回滚必须写 reason 字段，禁止静默删除。

## 第四章 终止与续跑

| 条件 | 动作 |
|------|------|
| 连续 3 次回测无改进 | 暂停 L2/L3，保留池子，写总结报告 |
| 池内启用因子达 20 | 暂停挖掘，等待人工评审 |
| 连续 5 批零新增 | 判定主题枯竭，切换挖掘方向（LLM 换 prompt / 换数据维度） |
| L4 连续 2 因子实盘回滚 | 暂停新因子启用，排查（过拟合/数据漂移），人工评审 |
| API 日预算耗尽 | 当日停止，次日恢复 |
| 数据完整性失败 | 暂停 loop + 告警，不自动跳过 |
| 人工介入 | 任何时刻可改宪法/停 loop，以人话为准 |

**事件总线（防死锁/活锁）**：各层不靠轮询，靠事件触发（回滚→补位 / 批完成→回测 / regime变化→复核 / 数据就绪→例行）。暂停状态不代表永久停止——任何上层事件都会重新评估暂停条件是否解除。事件定义与处理规则见 四层loop架构细则/工程保障.md 第四章。

**并发与互斥**：loop 是单进程消费者，全局文件锁防并发，锁带 TTL 与进程存活检测防僵尸。实现细节见 四层loop架构细则/工程保障.md 第三章。

**灾难恢复**：启动先做数据完整性扫描（日期连续性 + 关键字段非空率），失败则暂停 + 告警，不自动跳过。阈值见 四层loop架构细则/工程保障.md 第五章。

## 第五章 执行形态（运维）

1. **自动运行**：loop 以无状态批处理脚本运行（`factor_mining_loop.py`），每次运行从检查点恢复，跑完写报告退出。
2. **调度**：Hermes cron 每 2 小时自动跑一批（job: 量化因子挖掘loop）；也可手动触发。
3. **报告**：每次运行结束输出摘要（新增/启用/回滚/指标变化）。
4. **人工干预点**：新因子启用前 L3 判定是自动的，但**首次启用前**（池内第 1 个因子）需人工确认一次，之后按规则自动。
5. **人工标注反馈通道**：人工评审因子可打标签（「逻辑合理但 IC 弱」「黑箱但有效」「疑似过拟合」「叙事误导」）→ 记录档案 + 回喂 LLM prompt 优化。
6. **日常运维命令**：见 `D:\quant_project\README.md` 第三章（status / batch / smoke / l4-only / cron 查看）。
