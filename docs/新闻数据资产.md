## 一、目标

现有 45 因子全来自价/量/换手（纯量价维度）。新闻是**全新的信息维度**：市场情绪、事件驱动、热度变化——这些在 K 线里看不到。新闻因子管线把财经新闻转化为日频因子，经 L1-L4 标准流程验证后进 v7 打分。

**历史深度问题**：新闻因子需要历史数据才有回测意义。若只有"从现在开始采"，需等数月才能过 L3 回测——**落地前必须先确认历史数据可得性**（数据源 API 是否支持按历史日期拉取）。

## 三、处理管线（设计）

```
采集 → 清洗 → 关联 → 提炼 → 聚合为日频因子 → 接入 L1
```

1. **采集**：定时拉取（盘中每 5-10 分钟 / 收盘全量），落盘原始 JSON
2. **清洗**：去重（同源重复）、过滤广告/行情播报噪音、正文提取
3. **关联**：新闻 → 股票（名称/代码实体识别，用 `stocks_em.parquet` 名称映射）
4. **提炼**：情绪打分（正面/负面/中性 + 强度）+ 主题分类（公告/业绩/重组/监管/行业/宏观）——LLM 逐条打分（准但贵）vs 规则词典（便宜但糙）vs 混合
5. **聚合**：每日每股票 → 新闻情绪因子 / 热度因子 / 事件因子
6. **接入 L1**：作为候选因子走多周期 IC 体检（fwd_1d/5d/10d/20d）

## 四、存储设计（待建）

```
D:\quant_data\news\
├── raw\              # 原始采集 JSON（按日期分片，如 2026-08-16.jsonl）
├── parsed\           # 清洗+关联后的结构化数据（parquet：news_id, date, time, stock_code, sentiment, topic, intensity, source）
├── daily_factors\    # 聚合后的日频新闻因子（parquet：date, stock_code, 各因子值）
└── pit_snapshots\    # PIT 快照（与宪法 pit_snapshots 联动）
```

**PIT 红线（宪法强制）**：新闻必须按**发布时间**对齐交易日——T 日 15:00 前发布的新闻才能用于 T 日信号，晚于 15:00 算 T+1。禁止用当日盘后新闻回填当日因子（前视偏差）。

## 五、新闻因子候选（方向）

| 因子 | 定义 | 逻辑 |
|------|------|------|
| 情绪分 | 当日该股新闻情绪加权均值（-1~+1） | 正面情绪 → 短期动量/反转待验证 |
| 热度变化 | 当日新闻条数 / 5日均值 | 热度突增 = 事件驱动信号 |
| 事件冲击 | 突发利空/利好（强度×方向） | 公告/监管类事件 |
| 板块情绪 | 所属板块当日情绪均值 | 板块联动 |

> 具体因子经 L1 体检（|ICIR|≥0.25 + 同号段≥60% + 衰减<50%）后才有资格进池，规则与量价因子完全一致（见 四层loop架构细则/L1）。

## 六、接入方式

- **数据采集**：新脚本 `news_collector.py`（定时，cron 驱动）
- **提炼**：`news_factor_engine.py`（LLM 打分 + 规则兜底混合）
- **因子落地**：聚合为日频 parquet → 与 ic_data 结构对齐 → 走 `factor_mining_loop.py` 标准 L1-L4 流程
- **半衰期预期**：新闻因子大概率 short_lived（半衰期 <6 月），L4 评估周期自动缩短——符合宪法对短寿命因子的既定处理
