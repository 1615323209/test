## 一、定位

L3 是策略整合层。L1/L2 只证明因子"统计上显著且不被池子解释"，L3 回答"把它加进策略，收益是否真的提升"——用训练集判定、验证集复核，防过拟合；用多重检验校正防 p-hacking。

**本版新增职责**：L1 引入了 `role`（`score`/`exit`/`timing`）与 `label_spec` 两个维度，L3 必须为三类候选提供**三种不同的评估形态**——出场因子改的是出场规则、择时因子改的是权重，它们都无法用"注入打分后回测"来评估（现状只支持 `score` ⚠️）。

## 二、触发条件（数据就绪驱动，不用固定时钟）

|触发|条件|状态|
|---|---|---|
|批量触发|候选池新增 ≥3 个，或累计 5 批|✅|
|例行触发|`factor_daily_incr` 最新日期 ≥ 当日（或交易日 18:00 后）|✅|
|补位触发|L4 回滚因子 → 挑下一未测候选注入重测（事件驱动）|✅|

## 三、执行动作（按 `role` 分三种形态）

### 3.1 `role = "score"`（选股打分因子）✅ 现状唯一支持

1. 候选因子注入 v7 打分：`backtest_engine.run_backtest(extra_factors)`，形式为 `(expr).rank().over('日期')`
2. **训练集（2021-2024）回测**：六指标对比训练集基线
3. **验证集（2025-2026）复核**：训练集通过的因子单独回测

### 3.2 `role = "exit"`（出场/存活因子）🔧P2 新增

依据 v7 归因：**破 MA20 是最大出血点（46 笔占亏损 65%）**、**拿得住才赚钱（持有 20+ 天胜率 100%）**——当前最值钱的信号可能是"这只票能不能扛住持有期"，而不是又一个横截面反转因子（见 L1 第 8.2-B3）。

- **评估方式**：把候选作为出场规则的一部分注入回测（替换或追加到"破 MA20 减半 / 破 MA60 清 / 时间止损 20 天"这组规则），与**原 v7 出场规则**对比
- **主指标不同**（关键）：不看收益提升，而看

|指标|门槛|
|---|---|
|最大回撤改善|≥ 0.5%|
|或 亏损笔数占比下降|≥ 3 个百分点|
|且 总收益不恶化|≥ −0.5%|
|且 平均持有天数不显著缩短|防"提前跑掉"换来的假改善|

- **权重语义不同**：出场因子没有打分权重，档案记 `rule_version` 而非 `weight`，**不参与 `calc_weights`**（否则会污染打分因子的权重归一化）

### 3.3 `role = "timing"`（因子择时）🔧P2 新增

- **评估方式**：静态权重 vs 条件权重（候选作为权重调节器），对比六指标
- **v8 教训的正确读法**：v8 失败的是"弱市降仓"（**仓位**调整，减少分散导致单笔风险更大），不是"因子权重条件化"。两者不等价，**不能用 v8 的失败否掉这条路线**
- **额外要求**（防过拟合到少数切换点）：必须报告权重切换频率、切换点数量、切换点前后 20 日收益；切换点 < 10 次的候选一律判定"样本不足"，不启用

### 3.4 未就绪时的处置

3.2/3.3 的评估形态实现前，`role != "score"`的候选**只登记档案、不入池、不启用**（与 L2 第七章一致）。禁止用 `score` 的口径硬套——那会得出无意义的结论。

## 四、权重公式（信号强度归一化）

```
w_i = 0.05 × |ICIR_i| / median(|ICIR_pool|)
上限 0.10；下限 0.02
short_lived 因子：上限封顶 0.04（截断法，不保下限）
总权重约束：Σw ≤ 0.5（v7 六因子=1.0，新因子合计最多 0.5）
缩放后 <0.02 的因子剔除（"边际贡献不足淘汰"）→ 迭代直到全部 ≥0.02 且 Σ≤0.5
L4 实盘确认后可微调 ±50%（须重新过 L3）
```

**权重调整链** ✅：L2 算指标 → L3 定权重 → 总权重超限等比例缩放 → 跌破下限剔除 → 迭代收敛。

本版修正：

- 🔧P1 **ICIR 输入口径改为"设计段 + 可交易域" ICIR**。现状用全域 ICIR，其中包含停牌/涨跌停/次新等不可买样本贡献的假 alpha，会系统性高估那些"alpha 集中在不可交易域"的因子的权重
- 🔧P2 备选口径：用 `t_NW` 归一化替代 ICIR。同样本长度下两者单调等价，但跨不同样本长度（例如新数据维度只覆盖部分区间的因子）更可比
- 🔧P1 `half_life_unknown`（L2 半衰期算不出）按 `short_lived` 保守处理，上限 0.04——现状 L2 异常兜底返回 12 月，反而让算不出的因子拿到最高上限
- 🔧P2 `role != "score"` 不参与 `calc_weights`

## 五、判定标准（多重检验校正）

```
动态阈值：提升 ≥ 0.5% + 0.05×ln(N)
训练集提升 ≥ 阈值 且 验证集不恶化 → 启用
训练集达标但验证集恶化 → 回滚（过拟合）
两集均无提升 → 回滚
```

### N 的口径修正（🔧P1，重要）

现状 `N = 累计测试候选数`（`ck["cumulative_tested"]` 每评估一个候选 +1）⚠️，这**严重低估了实际检验次数**：

- L1 的修正轮每轮都看一次设计段指标（最多 3 轮）
- 同一表达式换 `label_spec` 算独立检验
- 被 L1/L2 拒掉的候选也消耗了检验次数

**修正**：`N = Σ n_peek`（L1 上报、L2 透传，见 L1 第二章 / L2 第二章）。

> ⚠️ **切换后阈值会显著上升**，`0.05` 这个系数必须重新校准：用 v7 六因子做回归验证——老因子在新 N 口径下应仍然过线；若全部不过线，说明系数过大，调系数而不是退回旧口径。

### 分段披露（🔧P1）

L1 用 2024 作为内层留出段做 G4 确认，因此**2024 对 L1 已不是完全干净的样本**。L3 报告必须分三段披露：

|段|区间|性质|
|---|---|---|
|设计段|2021-2023|L1/L2 全程可见，纯样本内|
|内层留出|2024|**已被 L1 用作 G4 确认**，不是独立 OOS|
|验证集|2025-2026|仅 L3 可见，唯一真外推|

训练集判定仍用 2021-2024 整段（策略级回测需要足够笔数——训练集基线只有 97 笔，切碎后无法判定），但**必须额外要求 2024 段不显著恶化**，且报告里注明 2024 的性质，防止把它误读为样本外证据。

### 验证集小样本降级 ✅（当前仅 9 笔）

- 验证集有效成交 < 20 笔 → 统计功效不足，判定降级
- 规则：验证集收益 ≥ −2% 即视为"不恶化"，不要求为正；训练集提升达标即可启用
- 标记 `degraded_enabled`：L4 预期基准降为 0，观察频率提高
- 验证集 ≥20 笔后恢复"必须为正"完整标准

## 六、调仓周期约束（2万资金成本闭环）

- 策略固定 **5 日周期轮动**（每周调仓一次；信号极端可触发式提前，单月 ≤6 次）✅
- 非调仓日只记录信号不触发交易 ✅
- L2 换手暴露检验用"5 日调仓口径"验证 ✅
- 本版补充：L1 的**信号自换手**门槛（rank 自相关 ρ(5日) ≥ 0.3）已在入口保证候选适配 5 日周期，L3 不必再为高频信号做特殊处理
- 目的：最低 5 元佣金约束下，高频换仓成本占比极高（v2 的教训是成本吃掉 37% 本金），5 日周期把成本锁进预期

## 七、监控落盘

`loop_state/backtest_history.csv`：因子组合 → 训练集六指标 → 验证集六指标 → N → 动态阈值 → 权重 → 判定 ✅

新增字段（🔧P1）：`role`、`label_spec`、`n_peek`、`N_effective`（=Σn_peek）、分段指标（2021-2023 / 2024 / 2025-2026）、权重输入口径标记、`rule_version`（exit 类）。
