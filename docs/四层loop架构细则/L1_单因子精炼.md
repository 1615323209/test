## 一、定位与边界

L1 是因子入口层：把任意来源的候选因子做**单因子层面**的体检，不合格的在入口淘汰，不浪费上层算力。

**L1/L2 分工原则（2026-08-17 修订）**：判断依据是"是否依赖因子池上下文"。

|归属|内容|理由|
|---|---|---|
|**L1**（单因子性质）|多周期 IC、覆盖率、可交易域一致性、分年/分段稳定、quintile 单调性、风格中性残差 IC、信号自换手|便宜、不依赖池、能早杀|
|**L2**（池上下文）|三通道去重、动态正交化、regime 分层、半衰期、持仓换手暴露|必须知道池里已有什么|

原分工把 quintile 单调性和换手放在 L2，导致大量"IC 漂亮但不可交易"的候选白白消耗 L2 的重活（正交化/去重都是全表运算）。本版把纯单因子性质下沉到 L1。

## 二、L1 内部样本切分（🔧P1，防选择偏差）

宪法规定训练集 2021-2024 / 验证集 2025-2026，L1 只能见训练集。但 L1 会**反复窥视**训练集（IC 反馈 → LLM 改公式 → 再算 IC），因此训练集内部必须再切：

```
2021-01-01 ─── 设计段 ──── 2023-12-31 │embargo 10d│ 2024-01-01 ── 内层留出 ── 2024-12-31 ║ 验证集 2025-2026（L1 禁止可见）
   ← IC 反馈 / 修正轮 / 阈值判定 →                      ← 仅 G4 一次性确认 →              ← 仅 L3 复核 →
```

- **设计段（2021-2023）**：全部生成、反馈、修正、G0-G3 判定的唯一口径
- **内层留出（2024）**：只在 G4 使用一次，**不反馈给 LLM**、不参与修正轮
- **embargo**：两段之间留 ≥10 个交易日空档，防 fwd_20d 标签跨段（fwd_20d 需 20 日，段末样本的标签落在下一段内 → 必须 purge 段末 20 日样本）
- **窥视计数 `n_peek`**：同一血统（lineage）每次看设计段指标记 1 次，随候选档案上报，作为 L3 多重检验 N 的输入（现状 N 只按候选数累加，低估了修正轮的窥视次数 ⚠️）

## 三、候选契约 FactorCandidate（🔧P2，统一三条生成线）

现状问题：LLM 走完整 L1；`formula_beam_search.py` 内嵌了第二套 L1 判定；Alpha360 产出的是预测列而非 polars 表达式，`validate_expr` 根本无法处理 ⚠️。三套口径无法互相比较。

统一契约（L1 只认这一种输入，生成器可插拔）：

```python
FactorCandidate = {
  "id": str,                       # 内容寻址：hash(payload + feature_deps)
  "source": "llm|beam|nn|human",
  "role": "score|exit|timing",     # 选股打分 / 出场存活 / 因子择时（见第八章目标轴）
  "payload": {"kind": "expr", "expr": "..."} |
             {"kind": "column", "column_ref": "...", "builder": "脚本+参数+commit"},
  "label_spec": {"kind": "fwd_ret|triple_barrier|max_dd",
                 "horizon": int, "up": float, "dn": float},  # 预测目标，默认 fwd_5d
  "declared_direction": +1 | -1,   # 生成时必须声明预期符号（见第五章 G2）
  "hypothesis": str,               # 一句话经济逻辑（可验证，非事后叙事）
  "feature_deps": [str],           # 依赖列，必须全部在 feature registry 内
  "pit_class": "price_volume|fundamental|news|derived",
  "lineage": {"parent_id": str|None, "round": int, "n_peek": int},
  "provenance": {"model": str, "temperature": float,
                 "prompt_hash": str, "response_hash": str},
  "cost": {"api_tokens": int, "compute_ms": int}
}
```

- `payload.kind == "column"`（深度学习类）额外要求：**必须提供 out-of-fold 预测**，禁止用拟合期内预测算 IC
- `provenance` 是复现的唯一依据（见第六章第 5 条）
- **`role` 是本版新增**：现状 loop 只支持 `score`（选股打分因子），而 v7 归因显示最大出血点在出场（破 MA20 占亏损 65%）——`exit`/`timing` 两类候选目前无通路，L3 也无法评估（见第十二章第 4 条）
- **`label_spec` 是本版新增**：默认 fwd_5d 均值收益，但允许与实际出场规则对齐的路径标签（triple_barrier：未来 N 日内先触及 +12% 还是 −8%）；同一表达式换标签算不同候选，`n_peek` 各自独立计数

## 四、执行流程：G0-G4 分级漏斗（🔧P2）

现状：每个候选无论好坏，都要跑 4 个 horizon 的全训练集 group_by 加一次 Normal IC，共 5 遍全表扫描；而 v1 的经验是 2340 个候选里绝大多数一眼就该杀。改为逐级变贵、能早杀早杀：

```
候选 → G0 静态(ms) → G1 抽样(s) → G2 主周期(10s) → G3 完整(min) → G4 留出确认 → 交 L2
         ↓ 拒          ↓ 拒          ↓ 拒            ↓ 拒            ↓ 拒
      已拒绝库（hash 记忆，同族候选不再重算）← 结构化诊断回喂生成器（≤3 轮）
```

|门|内容|数据口径|目的|
|---|---|---|---|
|**G0 静态**|AST 白名单、registry 列校验、PIT class、语义 hash 去重、比对已拒绝库|不读数据|毫秒级挡掉幻觉/泄漏/重复|
|**G1 抽样快筛**|设计段随机抽 15% 交易日算主周期 IC|设计段抽样|\|t_NW\| < 1.5（门槛半值）直接杀|
|**G2 主周期**|全量主周期 IC + 覆盖率 + 横截面离散 + 可交易域一致性 + 声明符号|设计段全量|挡掉假 alpha 与不可交易 alpha|
|**G3 完整体检**|多周期、衰减、分年/分段稳定、quintile 单调、风格中性、信号自换手、Rank vs Normal|设计段全量|完整单因子画像|
|**G4 留出确认**|内层留出一次性确认|2024|吸收设计段选择偏差|

**已拒绝库**很关键：现状同一表达式改个常数就会重算一遍全量 IC，修正轮里这种情况极常见。G0 用语义 hash（列名排序 + 数字归一化骨架，`expr_hash` ✅已实现）比对历史拒绝记录，命中即复用拒绝原因。

每级记录耗时与淘汰数 → `l1_log.csv` 变成漏斗表，可直接看出算力与 API 成本花在哪一级（见第九章）。

## 五、过线标准（按门分级）

> ⚠️ **阈值校准前不生效**：新口径必须先用 v7 六因子 + 池内已启用因子做回归验证——老因子在新阈值下应仍然过线；否则调整阈值而非放弃口径。

### G2 主周期（设计段 2021-2023，**可交易域口径**）

|检查项|阈值|目的|状态|
|---|---|---|---|
|主周期显著性|\|t_NW\| ≥ 3.0（Newey-West，lag=10）|修正重叠标签导致的 t 值虚高|🔧P1|
|声明符号一致|实测 IC 符号 == `declared_direction`|单边检验，消除双边 \|ICIR\| 的免费两次检验|🔧P1|
|每日有效截面|≥ 500 只|防"只在极小截面上有值"的假 IC|🔧P1|
|总覆盖率|≥ 60% 的股票×日|同上|🔧P1|
|横截面离散度|每日 std > 0 的天数占比 ≥ 95%|防常量/近常量因子（Spearman 退化）|🔧P1|
|可交易域一致性|\|IC_可交易 − IC_全域\| / \|IC_全域\| < 30%|差异过大标 `untradable_alpha`，不入池|🔧P1|

**t_NW 门槛与旧口径的关系**：设计段约 730 个交易日，旧标准 |ICIR|≥0.25 的裸 t = 0.25×√730 ≈ 6.75；fwd_5d 重叠 5 日，Newey-West 修正约除以 √5 ≈ 2.24 → t_NW ≈ 3.0。**新门槛与旧门槛严格度相当，只是把虚高的 t 修正回真实值。**

**可交易域定义**（与 L4 实际可买域对齐）：非停牌、非涨停、非跌停、上市 > 120 日、非 ST。全域 IC 仅作参照，**过线以可交易域为准**。

### G3 完整体检（设计段全量）

|检查项|阈值|目的|状态|
|---|---|---|---|
|次周期同号|fwd_1d/10d/20d 与主周期同号|信号跨周期一致|✅|
|IC 衰减|\|IC_5d\|→\|IC_10d\| 衰减 < 50%|防瞬时脉冲假因子|✅|
|分年符号一致|设计段每年 IC 同号；任一年反向且 \|t_year\|≥2 → 拒|**替代**"滚动 60 日 ICIR min > 0"|🔧P1|
|半年段一致|seg_ok_ratio ≥ 60% 且 last2_ok = True|分段稳定（旧文档已承诺，代码缺失）|⚠️→🔧P1|
|quintile 单调|\|mono\| ≥ 0.3（黑箱来源 ≥ 0.5）|防"极端层信号、中间层噪声"|从 L2 下沉 🔧P1|
|**Top-K 精度**|按声明方向取头部 K=20：平均 fwd_5d 超额 > 0，且 t_NW ≥ 2|与"Top 3 选股"对齐（见下）|🔧P1|
|**Top-K 稳健性**|K ∈ {10, 20, 50} 三档超额同号|防单一 K 值上的偶然|🔧P1|
|风格中性残差 IC|残差 IC ≥ 0.5 × 原始 IC|防因子只是规模/换手/波动的代理|🔧P1|
|信号自换手|rank 自相关 ρ(5日) ≥ 0.3|2 万资金 + 最低 5 元佣金下，换手过快无法落地|🔧P1|
|Rank vs Normal|同号；异号需 \|Normal\|≥2×\|Rank\| 且同向|重尾容忍|✅|

**为什么必须加 Top-K 精度**：v7 实际只买 **Top 3 / 约 5000 只 = top 0.06%**，而 IC 衡量的是全截面 rank 相关，quintile 单调最细也只到 top 20%——两者差三个数量级。一个 IC 平庸但头部干净的因子，对 Top3 策略的价值高于一个 IC 高但头部平坦的因子，而只看 IC 的漏斗会反过来选。Top-K 精度与 IC 并列（不替代：IC 稳定性仍是防噪的好指标），K=20 是"比 Top3 宽、又不至于退化成 quintile"的折中，且样本量足够算 t。

**为什么废掉"滚动 60 日 ICIR min > 0"**：三个问题——现有实现是步长 30 的抽样，不是真 min ⚠️；这条在筛"训练期内从未走弱"，本质是对平滑度的过拟合；单个 60 日窗口的 ICIR 噪声极大，min 由噪声决定。改为"分年符号一致 + 最差年份不显著反向"，经济含义更清楚也更抗噪。

**风格中性化口径**：对规模代理、`turn_ma20`、`vol_20d`、`ret_20d` 做逐日横截面回归取残差，用残差重算主周期 IC。残差衰减过多标 `style_proxy`——这类候选在 L2 的正交化里几乎必然被拒，但在 L1 拦下来能省掉全部 L2 重活。

**信号自换手 vs L2 换手暴露**：两者不同，都要。L1 测的是**信号本身翻动多快**（决定交易成本），L2 测的是**选出来的股票是不是高换手股**（选股风格暴露 ≤1.5）。

### G4 内层留出确认（2024，仅一次）

|检查项|阈值|状态|
|---|---|---|
|符号一致|与设计段同号（硬性）|🔧P1|
|显著性保留|\|t_NW_2024\| ≥ 0.5 × \|t_NW_设计段\| 且 ≥ 1.5|🔧P1|

## 六、安全与泄漏防线（🔧P0，最高优先）

### 1. 特征注册表取代 schema 白名单

**现状漏洞**：`validate_expr` 的白名单 = `ic_data` 全部列，而 `ic_data` 含 fwd_1d/5d/10d/20d；同时 `build_dict()` 只排除了 `fwd_5d`，**fwd_1d/fwd_10d/fwd_20d 被当成普通因子列（描述为"Float32 因子值"）写进数据字典喂给 LLM**。引用 `fwd_1d` 的因子与 fwd_5d 窗口重叠，IC 虚高且能通过全部检查一路进 L3。**这是 L1 当前最严重的单点风险** ⚠️。

方案：白名单改为显式 **feature registry**，每列带元数据：

```
{col, 中文含义, dtype, role: feature|label|meta, pit_safe: bool,
 as_of 语义, 最小可用滞后, 来源脚本}
```

- `role == "label"`（全部 fwd__）→ *_硬黑名单**，任何引用直接拒
- 未在 registry 注册的列 → 默认拒（现状是默认放行）
- 数据字典由 registry 生成，与校验共用同一份定义（消除"字典和校验两处各写一遍"的漂移）

### 2. AST 白名单沙箱取代裸 eval

**现状漏洞**：loop 主链路用 `eval(expr_str, {"pl": pl})`，未限制 `__builtins__`（`llm_factor_synth.eval_ic` 里有正则+空 builtins 限制，但主链路不走它）⚠️。LLM 输出的字符串等于任意代码执行入口。

方案：AST 编译器，只允许 `Name(pl)`、算子白名单内的 `Attribute/Call`、`Constant`、`BinOp/UnaryOp`；其余节点（Import/Subscript/Lambda/Attribute 非白名单）一律拒绝。**算子白名单是单一来源**，同时驱动校验和 prompt 生成。

### 3. 时序算子强制分组

**现状漏洞**：prompt 只要求 `rolling_*` 传 `min_samples`，不要求 `.over('股票代码')`。长表上不带 `over` 的 rolling 沿文件物理顺序滚动——按日期排序就是跨股票混算，按代码排序才是本股票历史，**结果取决于 parquet 排序，且跨股票混算会把同日其他股票的信息带进来**。

方案：AST 层强制 `rolling_*`/`shift`/`diff`/`cum*` 必须带 `.over('股票代码')`；禁止负数 shift（`shift(-n)` 即显式未来函数）；数据装载固定 `sort(['股票代码','日期'])`。

### 4. PIT 检查落地

**现状漏洞**：`NON_PRICE_COLS = set()` 是空集，所以"PIT 一致性检查"这一关**永远通过** ⚠️。宪法红线"非量价列未经 PIT 检查不得进池"目前无任何实现。新闻情绪因子（`新闻数据资产.md` 已规划接入 L1）一旦接入即时生效为前视炸弹。

方案：PIT 状态并入 registry（第 1 条）。`pit_class != "price_volume"` 的列必须有 `pit_safe=True` 且声明最小滞后；抽 5 个历史日期对照 `pit_snapshots` 校验后才写入 registry——校验发生在**注册时**（一次），不是每个候选一次（省算力且更可靠）。
### 5. 复现改为内容寻址缓存

**现状漏洞**：seed = `batch_id × 1000 + factor_idx` 只写进 prompt 文本，请求体里没有 seed 参数，temperature 还随轮次变（0.3/0.5）——"支持按 seed 重放完整修正轨迹"无法成立 ⚠️。

方案：不再声称 API 确定性。落盘 `{prompt_hash → request_body, response, model, temperature, ts}`，复现 = 重放缓存。`provenance` 字段进候选档案，审计按 hash 追溯。

### 6. 深度学习候选的泄漏门禁

**现状漏洞**：`train_alpha360.py` 用 2025-2026（宪法规定的验证集）做 early stopping 与选模（`if v_ic > best_val_ic: best_state = ...`），再把 val IC≈0.107 当外推证据 ⚠️。这违反宪法第二章样本切分原则，该数值不是干净外推。

方案：训练内部改用本文第二章的切分（设计段训练 / 2024 内层验证做 early stopping），2025-2026 只在 L3 复核时用一次；`payload.kind == "column"` 的候选进 L1 必须提交 out-of-fold 预测，否则 G0 直接拒。
## 七、生成层（🔧P2）

### 批量生成取代单候选生成

现状"一次 API 调用生成 1 个因子 × 最多 3 轮"，成本高。改为**单次调用出 8~10 个候选**，靠 G0/G1 廉价淘汰——单因子 API 成本可降一个数量级（直接改善工程保障要求追踪的"单因子平均成本"）。

### 结构化反馈取代"请提高 ICIR"

现状修正 prompt 只回传一个 icir 数字并要求"修改公式以优化 |ICIR|" ⚠️（既与旧文档承诺的"反馈多周期 IC/同号段/last2_ok"不符，也等于在教模型做数据挖掘）。

改为回传**结构化诊断**：卡在哪一级门、失败项、覆盖率与每日截面数、分年符号表、风格暴露、信号自换手。**明确禁止**"提高 ICIR/IC"这类指令性反馈；反馈只描述缺陷，由 LLM 从金融逻辑出发修正。

### 反冗余上下文与主题配额

v1（2340 候选）与 v2（612 候选）的实证结论是**独立主题只有 4-5 个**，且已被 v7 覆盖。生成端不做多样性约束，就会永远重挖"高换手×高波动反转"。方案：prompt 注入池内因子的主题聚类摘要 + 近期被拒主题清单 + 主题配额（要求从欠代表主题出题）。

### 修正轮规则

- 最多 3 轮；**提前放弃**：|t_NW| 比首轮低 20% 以上即终止该血统（旧文档承诺过，代码中无 ⚠️）
- 每轮 `n_peek += 1`，随档案上报 L3
- 修正轮只看设计段；G4 失败不进修正轮
- 已知代码缺陷：第 1 轮抛 API 异常时 `best_fail_reason` 从未赋值，第 2 轮 `elif` 分支引用它会 NameError，且该行在 try 之外会穿透出 `l1_refine` ⚠️

## 八、生成方法论：三轴（信息轴 / 目标轴 / 搜索轴）

> 本章 2026-08-17 重构。原版按**搜索算法**分三条（LLM / 深度学习 / RL），但三条都在**同一个信息集**里搜索，因此把三条并入"搜索轴"，并补上此前完全空缺的信息轴与目标轴。

### 8.0 一个必须纠正的前提

v1 的结论「2340 候选塌缩成 4-5 个独立主题、FDR 1619 个通过形同虚设」被当成了"日频量价挖不出东西"的证据，但它其实是**特征集的性质，不是市场规律**：45 个因子全部是 `(收盘, 成交量, turnover)` 三列的闭包变换。在一个由三列生成的空间里做两两组合，塌缩成 4-5 个主题是必然的。

现有数据资产中**已经可用但从未进入因子空间**的维度：

|未用维度|现状|可开主题|
|---|---|---|
|**开盘价**|45 因子中**零使用**（ATR 只用 高/低/昨收）|隔夜跳空 / 日内收益分解|
|**最高/最低**|仅用于 `atr_14` 与 `high_20d/60d` 区间|上下影线、日内振幅结构|
|**行业映射**|`stocks_em.parquet` 已有（含行业），未接入|个股 vs 同行业（现全是个股 vs 全市场）|
|**个股资金流**|`stock_fund_flow.parquet` 已采集，未成因子|主力/散户分歧|
|**板块资金流**|`concept_flow_api` / `industry_flow_api` 已采集，未使用|板块轮动|
|**扩展 5 因子**|`factor_extra_daily.parquet`（ILLIQ/量价相关/偏度/峰度）在独立文件，**未进 ic_data**|非流动性、彩票偏好|

**优先级判断：信息轴 > 目标轴 > 搜索轴。** 在信息集扩维之前，把 LLM 换成 RL 只是在同一口井里换个铲子——8.3 方向 C4 自己承认的"日频纯量价不加极强正则化必过拟合"正是信息不足的症状，不是模型不够好。

三轴的候选统一通过第三章 `FactorCandidate` 契约进入 L1，**共用同一套 G0-G4 判定**（现状是 LLM 与 beam search 各有一套 ⚠️）。

### 8.1 信息轴（换输入）——唯一能真正创造新主题的方向

**A1 日内结构分解（🔧P1，零采集，性价比最高）**

- 隔夜跳空 `gap = 开盘/昨收 − 1`；日内收益 `intraday = 收盘/开盘 − 1`（`ret_1d` 是两者的复合，现在只用了复合值）
- 上影线 `(最高 − max(开,收))/收盘`；下影线 `(min(开,收) − 最低)/收盘`；振幅效率 `|收盘−开盘| / (最高−最低)`
- 隔夜-日内拉锯：`gap` 与 `intraday` 各自的 20 日均值在横截面上的排序差
- **A 股制度理由**：T+1 让隔夜风险无法对冲，日内追涨与隔夜持仓意愿是两种不同行为；隔夜/日内收益的反向拉锯在国际市场被反复验证，且在散户占比高的市场更强
- **前置**：registry 必须补上 `开盘/最高/最低` 的中文含义——现状未描述列一律显示为"Float32 因子值"，LLM 实际上不会去用（见第十一章缺陷 15）
**A2 行业/板块相对化（🔧P1，零采集）**

- 行业内 demean / rank：`x − mean_industry(x)`，把"个股 vs 全市场"换成"个股 vs 同行业"
- 板块动量溢出：所属行业过去 5 日平均收益（**必须剔除个股自身**，防自引用）
- 龙头-跟风扩散：行业内 `rank(ret_5d)` 与个股自身 rank 的差
- **PIT 注意**：`stocks_em.parquet` 的行业是**当期快照**，历史回溯存在行业变更/借壳导致的前视；`pit_class = "derived"`，registry 注册时须说明滞后处理方式

**A3 资金流（🔧P2，文件已有）**

- 主力/散户净流入的 5/20 日累计、净流入占成交额比、主力-散户分歧度
- 与量价低相关，属 A 股特有信息
- **门禁**：先验证 `stock_fund_flow` 历史是否覆盖设计段 2021-2023 全段；不覆盖则该主题只能进档案观察，不得入池（否则 IC 只在子区间成立）

**A4 现成扩展因子并入（🔧P1，几乎免费）**

把 `factor_extra_daily` 的 ILLIQ / 量价相关 / 偏度 / 峰度 并入 registry 与 `ic_data`，让 L1 可见。这四个对应的正是已发表 anomaly（Amihud 非流动性、彩票偏好），等于免费拿到四个有强先验的主题。

**A5 分钟级日内特征（🔧P2，需采集，信息增量最大）**

开盘 30 分钟 / 尾盘 30 分钟收益、日内已实现波动、分时成交额分布偏度、大单占比。信息增量最大但采集与存储成本最高，**建议在 A1-A4 走完、确认"扩维确实能开新主题"之后再上**。

**A6 新闻/舆情（🔧P2）**：见 `新闻数据资产.md`，主要约束是 PIT 严谨性与打分成本。

### 8.2 目标轴（换预测目标与评价口径）

**B1 Top-K 精度作为一等指标（🔧P1，零采集）**——已写入第五章 G3。核心理由：策略只买 Top 3 / 约 5000 只（top 0.06%），而 IC 是全截面、quintile 最细到 top 20%，差三个数量级。

**B2 与出场规则对齐的路径标签（🔧P2）**

- `triple_barrier`：未来 N 日内先触及 +12%（止盈）还是 −8%（止损），与 v7 实际出场规则同口径
- 备选：未来 5 日最大回撤、未来 20 日是否破 MA20
- 理由：对 fwd_5d **均值收益**优化 ≠ 对"止损止盈 + 破 MA20 减半 + 20 天时间止损"这套规则下的**实际收益**优化

**B3 出场/存活因子类型（🔧P2，需 L3 配合）**

v7 归因里最刺眼的两条是"破 MA20 是最大出血点（46 笔占亏损 65%）"和"拿得住才赚钱（持有 20+ 天胜率 100%）"——说明当前最值钱的信号可能是**"这只票能不能扛住持有期"**，而不是再来一个横截面反转因子。`role = "exit"` 的候选预测持有期存活/最大回撤，不进横截面打分。**阻塞点**：L3 现在的判定是"注入 v7 打分后回测"，无法评估出场因子（见第十二章第 4 条）。

**B4 失败样本驱动生成（🔧P1，零采集）**

把 v7 实际亏损的交易作为 prompt 上下文（归因已明确：破 MA20、高换手、4/7/11/12 月），要求 LLM 生成**专门区分这些失败样本**的因子。等价于把 L2 的"对 v7 有增量"从事后检验提升为**生成目标**（boosting 式挖掘），比盲猜后再筛高效得多。

**B5 条件因子 / 因子择时（`role = "timing"`，🔧P2）**

不找通用 alpha，而找"在什么状态下 v7 的既有因子更准"。注意 v8 的教训：简单 regime 降仓失败了，但那是**仓位**调整，与**因子权重**调整不是一回事，不能用 v8 的失败否掉这条。

### 8.3 搜索轴（换算法）——扩维之前边际价值最低

**C1 LLM 当"文献复现研究员"而非"因子发明家"（🔧P1，零采集，先验最强）**

让 LLM 复现已发表 anomaly（Amihud 非流动性、异质波动率、MAX/彩票偏好、52 周高点、成交量冲击、隔夜-日内拉锯），再针对 A 股制度特征（T+1、涨跌停、散户占比、板块炒作）做适配改造。已发表 anomaly 有独立样本外证据，先验强；LLM 自由发明的表达式先验近乎为零——这也解释了为什么 v2 的新因子边际价值有限。

**C2 LLM 自由生成（✅ 已落地，保留）**

闭环：**Prompt → 代码生成 → 体检反馈 → 自我修正**。

1. **Prompt**：数据字典（由 registry 生成）+ 池内主题摘要 + 被拒主题 + 算子白名单
2. **代码生成**：输出 Polars 表达式 + `declared_direction` + `hypothesis`
3. **体检反馈**：G0-G3 结构化诊断回传（第七章）
4. **自我修正**：≤3 轮，只看设计段，计 `n_peek`

优势是因子带金融逻辑、可解释、多样，跳出纯数学拟合的黑箱；配合 `declared_direction`后，"金融逻辑"从事后叙事变成**可验证的事前约束**。实现：`llm_factor_synth.py`（DeepSeek API），待改造项见第六章第 1/2/5 条与第七章。

**C3 公式搜索：beam search / RL（✅ 已落地，降级）**

Agent = "公式生成器"：Action 选算子、State 是公式树、Reward 是体检结果；比遗传规划聪明之处在于能记住哪些算子组合有效。实现 `formula_beam_search.py`（rolling 系算子 + shift 动量 + 横截面 rank，Reward 为"过 L1 体检优先"）。初验发现 |ICIR|≈0.577 的候选（`vol_change_5d` 60 日波动率 / `vol_ratio`），因滚动 60 日 ICIR min=−0.013 被拦——**该拦截依据的正是本版废弃的规则**（第五章 G3），改为分年符号口径后需重新判定。

> 🔧P2 改造：beam search 不再自带判定逻辑，Reward 直接调用 L1 的 G0-G3，避免两套阈值漂移。

**C4 深度学习表示学习（✅ 已落地，降级 + 口径待修）**

不显式生成公式，让网络自动学特征：原始序列 → 网络 → 特征向量。

|代表架构|做法|适用|
|---|---|---|
|Alpha360|CNN 处理 30 天 K 线序列|序列模式识别|
|GRU-GBDT|GRU 提取时序特征 → XGBoost 预测|混合特征|

**关键约束**：日频纯量价数据上，不加极强正则化必过拟合（回测上天、实盘落地）。高频/另类数据效果远好于日频量价——**这正是应先做信息轴的理由**。实现：`build_alpha360_tensor.py`（30天×8特征张量，z-score，fwd_5d 标签，memmap 分块）+ `train_alpha360.py`（1D-CNN + dropout/weight_decay/early_stopping）。

> ⚠️ **初验结论作废**：原记录"val 外推 IC≈+0.107（ICIR≈0.65）"是在 2025-2026 上做 early stopping 与选模后得到的，属于验证集泄漏（见第六章第 6 条），**不得作为外推证据**。修正切分后需重跑，并以 out-of-fold 预测走 L1 体检。环境：torch 2.13 CPU（Anaconda python）。

**C5 既有因子的变换与条件化（🔧P2，被忽略的便宜方向）**

v1 只做了 x/d/p/r 四种二元运算，从没做过：时序标准化（`ts_zscore` 取代横截面 rank）、分位截断、条件门控（"仅在高换手子样本内取值"）、分段单调化。同一批基础因子换**变换族**，可以在不新增数据的前提下开出与原主题低相关的变体。

### 8.4 落地优先级（针对 2 万资金 / 5 日轮动 / Top3 的具体约束）

|序|方向|新增采集|预期价值|状态|
|---|---|---|---|---|
|1|A1 日内结构分解|无|高，开全新主题|🔧P1|
|2|A2 行业/板块相对化|无（映射表已有）|高，A 股炒板块特征强|🔧P1|
|3|B1 Top-K 精度|无|高，纠正筛选与策略错配|🔧P1|
|4|B4 失败样本驱动生成|无|中高，直击"对 v7 有增量"|🔧P1|
|5|C1 LLM 复现学术 anomaly|无|中高，先验强|🔧P1|
|6|A4 扩展 5 因子并入 registry|无|低但几乎免费|🔧P1|
|7|A3 个股资金流|无（需验证历史覆盖）|中，与量价低相关|🔧P2|

前 6 条全部零采集成本，可直接开工。C3/C4 保持现状、不再追加投入，等信息轴扩维后再回来评估。

### 8.5 通用门槛

任何来源、任何 `role` 的候选都走同一条漏斗：**G0 静态 → G1 抽样 → G2 主周期 → G3 完整 → G4 留出**（第四、五章）。附加要求：

- **黑箱来源（nn / beam）**：quintile 单调 ≥ 0.5，且必须提交 out-of-fold 预测
- **新数据维度（A1-A6）**：新列必须先进 feature registry 并完成 PIT 注册（第六章第 1/4 条），未注册列 G0 直接拒
- **`role != "score"`**：需 L3 支持对应评估方式；L3 未就绪前只能进档案，不得入池

## 九、输出

- **合格（过 G4）**：`FactorCandidate` + 全量指标（多周期 × 双口径 × 设计段/留出段）+ `n_peek` → 进 L2
- **不合格**：写入**已拒绝库**（hash + 卡住的门 + 原因），供 G0 复用与生成端反冗余，不物理删除（宪法红线）
- **IC 序列外置**（🔧P2）：现状 `_ic_series`（约千元素列表）被塞进 `ic_metrics`，跟着候选一路写进 `checkpoint.json` 的 pool，而 checkpoint 每处理一个候选就原子写一次 ⚠️。序列应落 `loop_state/ic_series/{cand_id}.parquet`，checkpoint 只留标量指标与路径
